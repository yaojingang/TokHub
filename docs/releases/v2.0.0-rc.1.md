# TokHub 2.0.0-rc.1

TokHub 2.0 把个人 AI 账号、受控授权和专属中转带进普通用户工作区。用户可以继续使用官方 API Key，也可以按部署配置连接 ChatGPT、Gemini 和 DeepSeek 账号。

## New Features

1. **连接个人 AI 账号**：普通用户可以在个人空间管理七家主流 AI 服务，并从已验证连接创建个人中转站。
2. **ChatGPT 和 Gemini OAuth**：ChatGPT 支持 Codex OAuth 与 localhost 回调助手，Gemini 支持 Google 官方 OAuth 和 Cloud Project 权限校验。
3. **DeepSeek 网页账号**：登录助手在用户点击后读取当前账号的 `userToken.value`，受管桥负责验证、协议转换和低频率转发。
4. **完整授权生命周期**：连接支持加密保存、自动刷新、登录态失效检测、重新授权、删除和审计。
5. **个人中转保护**：实验连接固定为个人范围，并执行单中转、低 QPS、并发限制和重新授权隔离。
6. **OpenCLI 本机浏览器连接器**：ChatGPT、Gemini 和 DeepSeek 可以通过用户电脑上的 Chrome 登录态执行受限 `whoami` 与 `ask` 任务，网页登录凭据保留在本机。

## Fixes & Improvements

1. **并发刷新更安全**：旧刷新任务无法把刚更新的授权标记为失效。
2. **回调配置更严格**：公网 OAuth 回调要求 HTTPS，本地开发只接受 loopback HTTP。
3. **版本和依赖更新**：运行时、Docker、Helm、OpenAPI 和 Agent Skill 统一为 `2.0.0-rc.1`，当前 Go 与 npm 可达漏洞扫描结果为 0。
4. **本机任务隐私保护**：设备令牌与任务租约只保存哈希，提示词和回答在调用方取走后清除，异常中断遗留内容在 10 分钟保留窗口后自动清理，第三方错误文本经过白名单映射。
5. **网页登录引导**：ChatGPT、Gemini 和 DeepSeek 均提供“打开登录页”和“识别当前账号”两个连续入口，已经登录的用户可以直接识别。

## Compatibility

- 官方 API Key 连接保持原有行为。
- `/api/public/*`、`/v1/status/*` 和 `/gateway/v1/*` 路径保持兼容。
- `/healthz` 保留 `status`，并增加 `version`。
- 数据库迁移向前兼容，升级前仍建议执行标准备份。
- 本机浏览器连接器默认关闭，需要 OpenCLI 1.8.6+、Chrome 扩展和部署方显式风险确认。
- 本机浏览器中转按 TokHub 用户与服务商统一执行最小间隔、小时与每日额度；每位用户对每家服务商最多保留一个本机网页连接，重新配对设备或重建连接不会重置保护窗口。
- 安全挑战、403、限流和适配器变化使用可持久化的冷却或锁定状态；403 至少锁定 24 小时，暂停与恢复操作不会绕过冷却。
- ChatGPT、Gemini 和 DeepSeek 本机适配器可以独立关闭，连接详情提供账号保护用量、重新识别、暂停和恢复操作。

## RC Acceptance

正式版发布前需要完成 ChatGPT、Gemini 和 DeepSeek 测试账号的授权、非流式请求、失效检测、重新识别和删除验证。支持流式协议的官方 OAuth 路径还需要单独完成流式请求与刷新验证。
