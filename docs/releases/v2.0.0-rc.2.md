# TokHub 2.0.0-rc.2

TokHub 2.0 RC2 将个人会员账号中转升级为官方客户端本地委托，并把消费者网页协议统一收口到本机实验室。

## 生产能力

| 平台 | 生产连接 | 对外模型别名 |
| --- | --- | --- |
| ChatGPT | 官方 Codex `app-server` | `chatgpt-personal` |
| Grok | 官方 Grok Build ACP | `grok-personal` |
| Gemini | 官方 API Key、Google Cloud OAuth | 用户选择的 Gemini 模型 |
| DeepSeek | 官方 API Key | 用户选择的 DeepSeek 模型 |

OpenAI、Kimi、豆包、Claude、千问和 Grok 的官方 API Key 路径继续可用。

## 官方客户端连接器

- 专用 Docker/Podman 容器运行，使用非 root 用户与只读根文件系统。
- Codex、Grok、Connector 分别使用命名卷，不挂载宿主机个人目录。
- 设备配对生成 Ed25519 密钥，请求带 60 秒时间窗与一次性 Nonce。
- Prompt 与结果只进入加密 Redis 临时载荷，交付后立即删除。
- `/v1/responses` 支持文本流式、非流式和 `previous_response_id` 多轮恢复。
- 图片、音频、工具、函数调用和 Anthropic Messages 返回 `422 unsupported_capability`。

## 账号保护

- 每个账号一个连接器、一个官方客户端连接、一个并发任务。
- 最小请求间隔 15 秒，每小时最多 20 次，近 24 小时最多 80 次。
- TokHub 对同一请求执行零重试，不执行账号轮换、代理切换或备用账号接管。
- 401 进入重新登录流程；403、安全挑战和身份变化进入安全锁定。
- 首次 429 至少冷却一小时；24 小时内第二次 429 需要人工恢复。
- 工具事件立即中断并进入策略锁定。

这些控制可以降低自动化暴露面。服务商仍可依据条款、套餐、异常行为和安全策略限制账号，系统不提供零风险承诺。

## 升级迁移

迁移 `0051_provider_policy_safety.sql` 会停用旧 ChatGPT Codex OAuth 与 DeepSeek 网页 Token 连接，擦除 Access Token、Refresh Token、ID Token 和 `userToken` 密文，并停用相关托管通道。Gateway Key 保留，便于用户迁移到官方 API 或官方客户端后继续管理。

OpenCLI 连接保留设备引用和审计记录，只能在显式实验室中使用。DS2API 从默认 Compose 和生产 Helm 中移除，只在 `lab` profile 下部署。

凭据擦除无法通过代码回滚恢复。升级前请确认生产环境已接受这一安全迁移。

## 部署入口

官方客户端功能默认关闭：

```env
TOKHUB_AI_OFFICIAL_CLIENT_ENABLED=true
TOKHUB_AI_OFFICIAL_CLIENT_TASK_TIMEOUT=3m
```

连接器镜像固定 `@openai/codex@0.148.0` 与官方 Grok Build `1.0.5`。xAI 当前没有在公共 npm Registry 发布可验证的 `@xai-official/grok@0.1.4`，因此镜像使用 xAI 官方二进制分发并校验 SHA256。

完整部署、策略复核、监控和验收步骤见 [AI 账号授权与个人中转运行手册](../AI_WEB_AUTH_OPERATIONS.md)。
