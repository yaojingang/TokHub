01 · Executive Summary

执行摘要与实施状态

TokHub 已增加统一的「网页登录授权」入口，并复用现有个人中转链路。三家平台采用一套框架、多级稳定性：Gemini 正式 OAuth，ChatGPT Codex 自托管实验适配，DeepSeek 官方 API Key 引导与 userToken 网页账号实验适配。

平台 首版登录方式 调用链路 发布等级 能否复用消费者订阅
Gemini Google OAuth 2.0，外部浏览器 官方 Gemini API 可生产 不能等同于 Gemini Advanced 网页订阅
ChatGPT Codex OAuth + PKCE，复制回调地址完成 ChatGPT Codex Responses 私有接口 自托管实验，默认关闭 仅限 Codex 权益范围，受平台策略约束
DeepSeek 开放平台 API Key；网页登录后导入 userToken 官方 DeepSeek API；DS2API 独立桥接 API Key 可生产；网页账号实验 网页账号实验可复用当前消费者登录态

推荐结论

  1. 新增认证适配层，把现有网关从「读取一个 API Key」升级为「解析一份受信任的 Auth Material」。
  2. 授权页只打开服务商官方页面。TokHub 接受官方授权结果和显式开启的 DeepSeek userToken.value，并拒绝密码、验证码、完整 Cookie 与 cf_clearance。
  3. 消费者权益连接固定为个人范围；ChatGPT Codex 固定 QPS 1、并发 2，DeepSeek 网页账号固定 QPS 1、并发 1，两者都限制单连接的活动中转数量。
  4. ChatGPT 私有接口适配拥有全局与提供商双层熔断开关，一旦出现条款、协议或稳定性变化，可在不回滚数据库的情况下立即停用。

本轮已确认并实施的 4 项决策

DECISION GATE
  1. 接受「网页登录授权」采用 OAuth、官方开放平台凭证或显式开启的 DeepSeek userToken.value。
  2. 接受 ChatGPT Codex 适配仅用于自托管实验环境，默认关闭，界面明确显示稳定性与条款风险。
  3. 接受 DeepSeek 同时提供官方 API Key 引导和网页账号实验适配。PoW 与 SSE 转换由独立 DS2API v4.6.1 桥接服务完成。
  4. 接受 OAuth 与消费者权益连接首版为个人范围，不开放工作区共享和成员分发。

最脆弱假设：OpenAI Codex 和 DeepSeek 网页私有协议继续允许当前桥接方式。两条路径都没有公开稳定性承诺，因此必须单独验收并保留随时关闭的产品开关。

02 · Scope

  • 让现有 OpenAI 兼容网关继续提供 /chat/completions、/responses 和流式输出。
  • 增加平台级开关、个人范围限制、审计、监控、告警和回滚手段。

范围外

  • 采集或代填服务商账号密码、短信验证码、MFA 秘钥。
  • 自动读取浏览器 Cookie、本地存储、系统浏览器配置文件或第三方密码管理器；DeepSeek 仅允许用户手动提交单个 userToken.value。
  • 绕过 Cloudflare、逆向 PoW、防机器人校验或服务商保护措施。
  • 把消费者订阅连接分发给工作区成员、公开用户或多租户池。
  • 承诺私有网页接口与官方 API 一样稳定，或承诺消费者订阅可以替代开发者计费。
术语说明：本文把「网页登录授权」定义为用户在服务商官方页面完成 OAuth 或官方凭证创建，TokHub 接收授权结果。它不等同于抓取浏览器 Cookie，也不等同于复制完整网页会话。

相对 sub2api 的升级点

  1. 多实例授权事务：sub2api 的 OAuth 会话主要保存在进程内存，TokHub 改用 Redis，支持多副本、TTL、一次性消费与跨实例回调。
  2. 用户与浏览器会话绑定：授权事务绑定 TokHub 用户、个人组织、当前会话哈希、服务商与回调类型，任何一项不匹配都失败。
  3. 稳定指纹：以服务商 subject、账号 ID 与认证方式生成 HMAC 指纹，刷新令牌变化不会制造重复连接。
  4. 刷新并发控制：进程内 singleflight 加 Redis 分布式锁，100 个并发请求只允许一个刷新请求访问服务商。
  5. 平台级风险等级：官方、实验、不可用三档同时进入注册表、界面、审计和开关，避免用同一种「已支持」标签混淆稳定性。
  6. 许可隔离：TokHub 主程序独立实现授权与风控。DS2API 作为单独进程运行，保留 AGPL-3.0 许可和上游源码地址。
核心判断
sub2api 证明了消费者权益转接在工程上可运行。TokHub 需要补齐普通用户场景下的多租户隔离、授权回放防护、续期竞争、条款分级和紧急关闭能力，才能进入可控试用。
04 · Architecture

总体架构与关键接口

选定方案采用「认证适配器 + Auth Material 解析器 + 现有协议转换器」。连接中心负责授权与状态，网关只拿到一次请求所需的短生命周期认证材料，服务商差异不会散落到各个 Handler。

核心接口

type AuthAdapter interface {
    Capabilities() CapabilityProfile
    StartAuthorization(ctx, StartInput) (AuthorizationStart, error)
    CompleteAuthorization(ctx, CompleteInput) (CredentialBundle, AccountProfile, error)
    Refresh(ctx, CredentialBundle) (CredentialBundle, error)
    Revoke(ctx, CredentialBundle) error
    ResolveAuthMaterial(ctx, Connection, CredentialBundle) (AuthMaterial, error)
}

type AuthMaterial struct {
    Endpoint  string
    Headers   map[string]string
    ExpiresAt time.Time
    Mode      string
}

关键设计决定

  • AuthMaterial.Headers 只能由内置适配器产生，数据库与用户输入不能写入任意出站请求头。
  • 访问令牌、刷新令牌与 ID Token 作为一个加密 JSON 包原子更新，避免部分字段轮换造成不一致。
  • 网关不缓存明文刷新令牌，只在请求作用域内解析所需材料，日志与错误信息统一脱敏。
  • API Key 继续走现有路径，迁移完成后由同一个解析器返回 Bearer 或服务商专用请求头，保持现有连接兼容。
05 · Provider Adapters

三家平台适配方案

三家平台共享连接状态、加密、续期和监控框架。认证来源、回调方式、运行时接口和发布等级由提供商清单明确声明，前端据此展示不同交互。

ChatGPT：Codex OAuth 实验适配器

候选路径优点限制结论
直接复用 Codex OAuth + 私有 Responses 符合现有网关协议，改造量可控，sub2api 已验证工程可行 固定 localhost 回调、官方客户端身份、私有接口漂移与条款风险 选为自托管实验路径
官方 codex app-server 侧车 Codex 管理登录、刷新与限额 引入 Rust/Codex 运行时；输出是 Codex Agent 事件，可能执行工具，无法稳定模拟通用模型 API 不进入首版，可作为独立 Codex Agent 产品评估
OpenAI 开发者 API Key 正式、稳定、已支持 无法复用 ChatGPT 消费者权益 继续作为生产默认

授权流程

  1. 用户完成 TokHub 密码二次验证，创建 10 分钟授权事务。
  2. TokHub 生成 256-bit state、PKCE verifier 与 challenge，打开 auth.openai.com。
  3. OpenAI 固定回调到 http://localhost:1455/auth/callback。用户复制浏览器地址栏中的完整回调地址并粘贴回 TokHub。
  4. TokHub 解析 code 与 state，常量时间比对，交换 access、refresh 与 ID token；授权事务立即删除。
  5. 从已验证的 JWT claims 提取稳定账号 ID，生成 HMAC 指纹；不把邮箱或完整账号 ID写入日志。

运行时与限制

  • 固定上游为 https://chatgpt.com/backend-api/codex/responses，不允许用户修改域名、路径或代理头。
  • 只支持 Responses 与可无损映射的 Chat Completions 子集；图片、文件、网页搜索、持久会话和工具执行首版关闭。
  • 连接固定为个人范围，默认 QPS 1、并发 2、单连接仅允许 1 个活动中转密钥。
  • 401 触发一次刷新与一次重试；403、客户端身份拒绝、协议结构变化立即转为 attention 并打开平台熔断评估。
  • 界面显示「实验」标识和最后验证时间，部署端必须显式设置风险确认开关才能启用。

Gemini：正式 Google OAuth

  1. TokHub 使用自有 Google Cloud Web Application OAuth Client，回调固定为 {TOKHUB_PUBLIC_URL}/api/me/ai-authorizations/google/callback。
  2. 授权请求使用 state、PKCE、access_type=offline 和最小权限；生产域名、隐私政策与 OAuth 品牌审核按 Google 要求完成。
  3. 用户或部署方提供计费项目 ID，运行时发送 Bearer token 与 x-goog-user-project，调用官方 Gemini API。
  4. Google 未返回新 refresh token 时保留旧值；invalid_grant 直接进入重新授权，网络错误采用退避。
产品说明必须明确：Google OAuth 解决授权与项目访问，它不会把 Gemini Advanced 网页订阅自动转换成 Gemini API 配额。若用户希望使用个人 Google Cloud 项目，应填写有权限且已启用 Gemini API 的项目 ID。

暂不采用 Gemini CLI / Google One 私有桥接

sub2api 的 Gemini Code Assist 与 Google One 模式能接近消费者权益，但依赖内置 CLI 客户端身份、项目发现和非公开稳定性。首版把这条路径保留在研究清单，待取得正式许可或独立完成条款评审后再进入实验适配器。

DeepSeek：官方开放平台与网页账号双路径

  1. 新增「前往 DeepSeek 开放平台创建密钥」按钮，以新标签页打开官方控制台。
  2. 用户返回 TokHub 粘贴 API Key，沿用现有加密、模型验证和个人中转流程。
  3. 连接中心仍显示为统一的网页引导入口，但认证方式标记为 api_key_guided。
  4. 实验方式引导用户登录 chat.deepseek.com，从 Local Storage 的 userToken 对象复制 value。
  5. TokHub 严格校验输入，通过 DS2API v4.6.1 发送真实最小生成请求，验证成功后加密保存。
  6. 网页账号连接固定个人范围、单中转、QPS 1 和并发 1，401 会进入 reauth_required。

DeepSeek 当前没有公开的消费者 OAuth 或网页会话委托接口。网页账号方式依赖私有协议，默认关闭并要求部署端完成固定风险确认。TokHub 接受单个 userToken.value，完整 Cookie、密码、验证码与 cf_clearance 均被拒绝。

标准 OAuth 流程

  1. 用户选择 Gemini，阅读授权说明，完成 TokHub 密码二次验证。
  2. 前端调用授权开始 API，收到 authorizationUrl、transactionId、有效期和轮询间隔。
  3. 浏览器通过用户点击打开 Google 官方页面，不使用 iframe 或受 TokHub 控制的嵌入式浏览器。
  4. Google 回调 TokHub，后端完成 code exchange、加密保存、最小模型验证和连接创建。
  5. 回调页通过同源 postMessage 通知原页面并关闭；弹窗被拦截时显示「授权完成，返回 TokHub」。

ChatGPT 复制回调流程

  1. TokHub 打开 OpenAI 官方授权页，同时保留授权面板。
  2. 浏览器跳转到 localhost 后可能显示无法访问，面板提前说明这是固定回调行为。
  3. 用户复制完整地址，粘贴到 TokHub；前端只提交 URL，后端解析 code 与 state。
  4. 粘贴内容最多 8 KB，只允许 http://localhost:1455/auth/callback，拒绝其他 scheme、host、path 与重复参数。

07 · Lifecycle

登录态续期与失效处理

登录态管理采用主动续期与请求时兜底两条路径。后台任务提前刷新，真实请求只处理临界状态和 401，所有竞争都汇聚到同一个连接锁。

刷新算法

  1. 后台工作进程每分钟查询 next_refresh_at < now() 的连接，单批次上限由配置控制。
  2. 令牌到期前 5 分钟进入刷新窗口，并加入 0 至 60 秒随机抖动，降低同一时刻集中刷新。
  3. 先进入进程内 singleflight，再获取 Redis 锁 ai-auth:refresh:{connectionID}，锁 TTL 30 秒。
  4. 未获得锁的请求最多等待 2 秒，然后重读数据库；仍无新版本时返回可重试的 503，禁止各自刷新。
  5. 刷新成功后通过乐观版本号原子更新密文、过期时间和版本；旧刷新结果无法覆盖新凭证。
  6. 401 只允许触发一次强制刷新和一次上游重试，避免循环；已写出流式首字节后不重试。

错误分类

类别例子系统动作用户状态

08 · Security

安全、风控与隐私

这项能力会把普通用户的长期授权带入 TokHub，风险级别高于 API Key 表单。安全策略围绕「少拿、短存、强绑定、可撤销、可关闭」展开。

凭证与授权安全

威胁控制措施失败策略
CSRF 与登录串号state 256-bit、PKCE S256、TokHub 用户/组织/会话哈希绑定、SameSite=Lax任一不匹配立即拒绝，绑定不匹配不会破坏合法事务
回调重放Redis Lua 原子校验绑定并删除、10 分钟 TTL、code 只使用一次第二次返回 409
账号被盗后追加连接TokHub 密码二次验证，10 分钟 step-up grant失败 5 次冻结新增授权 30 分钟
凭证泄漏AES-256-GCM、版本化 keyring、密文 JSON 包、日志字段红名单缺失密钥时服务拒绝启动或连接失败关闭
SSRF 与请求头注入域名、路径、Header 全部来自内置适配器 allowlist用户配置无法覆盖
刷新风暴singleflight、Redis 锁、抖动、指数退避等待新版本或返回 503
连接删除后仍可用先禁用路由、吊销中转密钥并擦除密文，再在 5 秒边界内尝试撤销服务商 token撤销结果进入审计，路由始终保持关闭
条款或协议变化全局与平台双层 kill switch，适配器版本与策略版本入库立即停用实验路由

个人中转风控

  • OAuth 与消费者权益连接首版固定 sharing_scope=personal，界面隐藏成员与工作区分发入口。
  • ChatGPT 实验连接固定 QPS 1、并发 2，同一连接只允许一个活动或暂停状态的个人中转。
  • 刷新任务按服务商设置并发、QPS 与单次超时，结合 singleflight、Redis 分布式锁、抖动和分级退避控制刷新流量。
  • 请求正文、Prompt、图片和文件不进入审计日志；只记录请求 ID、模型、字节数、状态码、耗时与计量。
  • 网关仅在首字节写出前对 401 执行一次刷新和重试，实验并发保护不可用时直接返回 503。

下一阶段风控增强

可继续增加服务商与模型维度的 429 自适应冷却、多来源异常检测、重复账号风险事件和自动暂停策略。这些项目保留为后续迭代，不计入本轮已交付范围。

删除语义
用户删除连接后，所有受管通道立即关闭，个人中转密钥立即吊销，数据库凭证密文在同一事务内擦除。服务商撤销调用在 5 秒边界内执行并记录审计结果，不阻塞本地关闭。

成功标准

  • 所有现有 API Key 连接、快速中转与网关测试保持通过。
  • Gemini 可以从授权开始走到自动续期，并完成一次真实个人中转请求。
  • DeepSeek 用户可选择官方开放平台 API Key 或网页账号 userToken，并在同一页面完成连接与个人中转。
  • ChatGPT 实验连接在开关关闭时无路由、无入口、无后台刷新；开启后只允许个人范围和受限协议。
  • 任何 token、code、Cookie 与 Prompt 均不出现在应用日志、审计元数据或 Prometheus 标签中。
  • Redis 暂时不可用时禁止开始新 OAuth；现有仍有效 token 可以继续请求，刷新失败不会形成风暴。

发布与回滚

  1. 先发布数据库迁移与关闭状态的后端，确认 API Key 回归。
  2. 发布前端入口，注册表只返回已开启平台，避免空入口。
  3. Gemini 按内部账号、5%、25%、100% 四档灰度，逐档观察授权完成率与刷新失败率。
  4. DeepSeek 开放平台引导可直接启用；DeepSeek 网页账号和 ChatGPT 仅在自托管测试部署开放。
  5. 回滚优先关闭平台开关；Auth Resolver 回退到 API Key 分支，OAuth 数据保留但停止解密和刷新。
  6. 若必须回滚应用版本，新列保持向后兼容；0047 与 0048 不做破坏性 down migration，后续维护窗口再清理。
